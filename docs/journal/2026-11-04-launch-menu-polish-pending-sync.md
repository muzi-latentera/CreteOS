## Design and implementation

Launch dialogs use a document-body portal, outside the game-detail transformed tree and its viewport-sized heading rule. The old dialog had content-box sizing, padding added outside its height limit, a heading inheriting the detail page's responsive size, and footer actions inside the scrolling form. New bounded border-box dialog has a fixed header/footer and a min-height0, independently scrolling body. Focus moves scroll only the relevant control into view. Default screen keeps network, display preset, quality summary and Play/Cancel. Detailed quality/host-app controls are disclosed under Stream options; refresh/open-client actions under Host & connection tools. Existing pair/error/offline paths remain visible when relevant. All providers share the restrained Crete palette and sizing; ASOBI/Luna settings use the same surface.

Network and quality fields use the existing React choice list for pointer, keyboard and controller paths. Focus has a warm filled row/bar/border, distinct from the saved option's checkmark. Browsing does not save. B/Escape closes the picker first and restores the field, then closes settings and returns to the originating Play/launch button. Keyboard option confirmation explicitly consumes Enter and its release to prevent a native Windows picker opening behind the React list. A delayed network-preference write restores focus only if it fell back to the document body. Disabled selected Custom presets focus the first enabled option; long lists scroll, Home/End work and Tab can reach Back. Left/right in the two-column quality fields moves focus without silently changing a value. Existing backend launch/profile/pairing/network/cover logic unchanged.

Crete settings now have a section heading, bounded readable width and consistent understated rows, grouping and focus treatment; other themes retain their styling and settings values are unchanged.
