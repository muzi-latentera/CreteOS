# Optional home Wi-Fi switching

The native launcher invokes the installed per-device WiFiSmart.ps1 with PrepareSession before Moonlight, GeForce NOW or Amazon Luna launch. The hook is a no-op when the helper is absent. Foreign networks, disconnected Wi-Fi and paused automation are left alone. An unavailable preferred home network falls back to the current connection without blocking play.

Home Wi-Fi appears in the Moonlight and GeForce NOW launch settings. For Luna, open the game's Launch options arrow and choose Amazon Luna Wi-Fi. Choices are Automatic, Hyperoptic Extra, Hyperoptic Fibre E433 and Keep current connection. Preferences are remembered per service in CreteOS/stream_wifi_preferences.json, separately from display/game profiles. Automatic selects GamingProfile (Extra) for Moonlight and DownloadProfile (Fibre E433) for GeForce NOW and Luna. Choices map to the existing helper config, not arbitrary SSIDs or exported credentials.

The native launch creates a session lease before network preparation. The helper holds the actual current connection throughout preparation and play. An existing session wins over a second launch's preference. Moonlight releases its lease when its owned client/session ends; GeForce NOW releases on its native Done event or watcher completion; Luna tracks its matched PWA window until it closes, including time in its library. Closing Luna after play resumes the normal rules. Closing or crashing CreteOS invalidates its leases; dead/reused owner PIDs are ignored. External Moonlight/GeForceNOWStreamer process protection remains. Leases are released on launch errors too. No fixed manual override is left behind. The legacy PrepareGaming mode remains for older installed launchers.

The helper selects the download profile for Steam download state, active Windows Delivery Optimization jobs, or two sustained15-second receive samples above256KiB/s. This generic transfer fallback covers Epic/GOG/browser downloads without depending on private launcher log formats; it also classifies other sustained heavy traffic. It returns to the gaming profile after120seconds of low traffic, with a five-minute minimum download-profile residence. Steam/DO completion does not force a switch during an existing stream. Moonlight and GeForceNOWStreamer processes protect the current connection; direct launches outside CreteOS cannot guarantee a pre-launch switch. Manual Gaming mode is available for other browser-based cloud sessions or a direct external client launch.

The source pack does not include wireless credentials or a device-specific config. Installation supplies Enabled, Interface, InterfaceGuid, GamingProfile and DownloadProfile in config.json and uses already-saved Windows WLAN profiles. No keys are exported. Monitor/Status/DryRun and manual Gaming/Download/Auto/Pause modes are supported. Manual overrides last two hours; Pause lasts until Auto or a manual mode is selected. Only visible saved home profiles are selected; other networks and disabled/disconnected Wi-Fi are not overridden. A logon task starts Monitor hidden. No router/DNS/driver changes.

Run Test-Policy.ps1 and Test-Sessions.ps1 with Windows PowerShell5.1. DryRun observes the current connection and transfer hints without connecting or writing monitor state. WiFiSmart.ps1, Policy.ps1 and Sessions.ps1 must be installed together under the current user's native LocalAppData/CreteOS-Bootstrap/WiFiSmart, then restart the monitor task. Actual switching and network reachability must be verified on the device; policy tests do not establish performance.

In Automatic mode, startup and Windows resume notifications select the gaming profile first when it becomes available. Downloads that resume afterwards can select the fast profile again. The helper subscribes to Win32_PowerManagementEvent7/18, with a long-sample-gap fallback. Existing stream protection, Pause and explicit manual overrides remain higher priority. Hibernate/resume behavior still requires physical acceptance on the G1.


Windows' cached available-network list can contain only the current AP even while both home networks are in range. When a requested target is missing, the helper requests a native WLAN scan and rechecks visibility before connecting. It rechecks stream protection immediately before the connect call. Pre-launch preparation has a bounded20-second wait for scanning, association and profile confirmation.

# Optional G1 AX210 driver recovery

`Repair-Ax210Driver.ps1` is a manual, device-specific troubleshooting helper. It defaults to read-only `Inspect`. It requires an exported package folder with its per-file `manifest.json`, valid signed catalogs and the exact AX210 hardware match. Explicit `Previous` selects the preserved 23.150.0.4 package; `Current` selects preserved 24.80.0.2. Applying requires Windows administrator approval and refuses an open streaming client. It pauses/restores a running monitor during installation, retains both driver packages and never restarts Windows automatically. Check live PnP/adapter version after applying: the signed-driver inventory can lag. This helper is not a startup task or a claim that a driver rollback proves the root cause. Review the device recovery guide before use on another machine.


## Wired-aware operation — 4 November 2026

Copy `Network.ps1` together with `WiFiSmart.ps1`, `Policy.ps1` and `Sessions.ps1`; the four files are a matched deployment. NetworkStatus and the monitor use the OS-selected IPv4 route and an operational Ethernet interface, not merely cable presence. Disconnected, virtual/VPN and non-selected adapters are not treated as wired. Moonlight preparation checks the actual host destination; cloud preparation/idle policy checks the internet route. A wired route suppresses pre-launch WLAN changes for every saved choice and suppresses idle/download/resume switching. Network choices become Wi-Fi fallback choices. The helper does not change adapter metrics, disable interfaces, bind client sockets, override VPN routes or promise uninterrupted mid-stream cable removal. IPv6-only route classification is not added in this change.

When the wired route disappears, the existing saved Wi-Fi rules resume; active-client/session protection still wins and foreign networks remain untouched. NetworkStatus is read-only and returns no Wi-Fi credentials. A status-query failure is best effort and does not block launching. PrepareSession still creates/releases its existing lifecycle lease; it does not leave a fixed network override. Live dock check used ASIX Gigabit Ethernet2, with both Bosgame and internet routes wired. Physical unplug acceptance remains a user test; policy fallback was verified with fixtures.
